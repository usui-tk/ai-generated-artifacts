## 6. CRITICAL FINDING: Server 2025 install.wim の直接検査結果

### 6.1 検査内容

Server 2025 EVAL ja-jp ISO (`WS2025_ja-jp.iso`, 7,929 MB) の `install.wim` (6.86 GB) を `/ReadOnly` でマウントし、`\Windows\Boot\` 構造と `bootmgfw.efi` の Authenticode 署名を検査。

`bootmgr.efi` も同様に PCA2011 で署名されている(`signtool /verify /pa /all` で primary signature 1 個のみを確認、クロスサインなし)。

### 6.4 セッション中盤の私の仮説の誤り

セッション中、Step 5c-3 の結果(Server 2025 LCU に `_EX` 関連が一切含まれない)を見て、私(Claude)は次の仮説を立てました:

> 「Server 2025 は出荷時から PCA2023 ネイティブ署名されており、`_EX` バリアントは不要」

この仮説は **Step 5d の install.wim 直接検査で完全に否定** されました:

- ❌ install.wim の bootmgfw.efi は **PCA2011 で署名されている**(PCA2023 ではない)
- ❌ EFI_EX ディレクトリは **存在する**(不要ではない)

### 6.5 真の仮説(修正版)

**「Microsoft は Server 2025 から、PCA2023 staging assets (EFI_EX/Fonts_EX/DVD_EX) を install.wim に組み込んで出荷するように設計を変更した」**

これにより、4 OS の install.wim 設計は以下のように整理できます:

| OS | install.wim 出荷時の EFI_EX | LCU 経由の EFI_EX 提供 | EFI_EX 取得経路 |
|---|:---:|:---:|---|
| **Server 2016** | **未確認**(おそらく無) | **あり**(6 種バイナリ) | LCU 適用 → WinSxS → install.wim 経由 |
| **Server 2019** | **未確認**(おそらく無) | **あり**(6 種バイナリ) | 同上 |
| **Server 2022** | **未確認**(おそらく無) | **あり**(6 種バイナリ) | 同上 |
| **Server 2025** | **あり(72 files)** | **なし** | install.wim にネイティブ組込済 |

**未確認** の 3 OS については、次セッションで同様に install.wim 直接検査を実施して確証を取る必要があります(§9 参照)。

### 6.6 重要な含意

- Server 2025 install.wim 内の `bootmgfw.efi` は **PCA2011 署名** ですが、隣接する EFI_EX ディレクトリには **PCA2023 署名された `bootmgfw_ex.efi` 等が含まれているはず**(本セッションでは中身まで未検査 → 次セッションのタスク)
- `P10 ConvertPca2023BootManager` は **依然必要**(install.wim の EFI を EFI_EX で置換する処理)
- ただし Server 2025 では **LCU 適用なしでも EFI_EX が手に入る** ため、`EnableInstallWimUpdate=false` のままでも Healthy ISO を生成できる可能性が高い

## 7. Pipeline 設計への影響(現行コード継続使用 + 設定の見直し)

### 7.1 結論: 現行コード(P07/P09/P10)はそのまま使える

r07.0 で導入された `Invoke-BuildPhase10_ConvertPca2023BootManager` の **skip-with-warn 機構は維持** しつつ、`Get-IsoBootCertReadiness` の評価が `Healthy` になれば自動的に実行される設計は正しい。**コードに変更不要**。

ただし、各 OS の `config-Server*.json` の **設定値の見直し** が必要です。

### 7.2 推奨される config-Server*.json の調整(暫定案)

| OS | EnableInstallWimUpdate | PatchBaseline | Pca2023.RequiredByDefault | 期待される Health 推移 |
|---|:---:|---|:---:|---|
| Server 2016 | **true に変更**(現状: 未設定) | KB5087537 + KB5087065(現状維持) | true(現状維持) | Critical → Healthy |
| Server 2019 | **true に変更** | KB5087538 等を追加 | true | Critical → Healthy |
| Server 2022 | **true に変更** | KB5087545 等を追加 | true | Critical → Healthy |
| Server 2025 | **false のまま可** | (任意、セキュリティ目的のみ) | true | **既に Healthy(LCU なしで)** |

### 7.3 Server 2025 用の特別なフラグの是非

セッション中盤の仮説に基づき、私は「Pca2023.SkipConvertPca2023BootManager: true」のような特別フラグを提案しましたが、**この特別フラグは不要** です。理由:

- P10 は依然必要(boot.wim の EFI を EFI_EX で置換する処理は全 OS 共通)
- Server 2025 は LCU を待たずに最初から `Get-IsoBootCertReadiness` が Healthy になる可能性が高い
- 設定としては「`EnableInstallWimUpdate=false` でも構わない」程度
